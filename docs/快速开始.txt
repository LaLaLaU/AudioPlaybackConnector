AudioPlaybackConnector LAN 0.1.0 — Windows 10/11 x64

这个版本直接使用 Windows 播放声音采集与播放接口，无需 Voicemeeter、VB-CABLE 或“立体声混音”。
接收电脑开始接收后会在局域网广播，发送电脑的列表里可以直接选择，不用手填 IP。单向工作。两台电脑都运行 AudioPlaybackConnectorLAN.exe。
本程序是原蓝牙接收工具的局域网扩展模块；原版蓝牙程序仍单独运行。

一、当前电脑接收
1. 双击 AudioPlaybackConnectorLAN.exe，停留在“接收声音”。
2. 选择本机实体网卡的家庭局域网 IP，选择耳机或音箱。
3. 保持端口 29864、缓冲 120 ms，点击“开始接收”。
4. 两边默认使用同一个连接码 APCL-HOME-2026，不用填写。
   只有换过连接码时，才需要点“复制连接信息”转到 SUPERU。

二、SUPERU 发送
1. 将整个发行包解压到 SUPERU，双击同一个程序，切到“发送声音”。
2. 连接码已默认填好。等接收电脑出现在“接收电脑”列表里，选中它会填写 IP 和端口。
   列表暂时为空时，也可以直接输入 IP。换过连接码时，点“粘贴连接信息”会自动填写 IP、端口和连接码。
3. 选择 SUPERU 实际播放游戏 / 浏览器声音的设备，点击“开始发送”。
4. 播放音乐或游戏。接收电脑显示“接收中 · 来自 …”后检查耳机音量。

三、网络设置
两台电脑接到同一个家庭路由器，有线或 Wi-Fi 都可以；访客 Wi-Fi 可能禁止电脑互访。
家庭网络需设为“专用”。Windows 防火墙提示时允许本应用在专用网络通信。
如不想手动寻找设置，发行包附有 Configure-HomeNetwork.ps1；它默认只预览，不修改。
可在管理员 PowerShell 手动运行（按实际网卡名填写）：
  .\Configure-HomeNetwork.ps1 -InterfaceAlias '以太网'
确认预览后添加 -Apply 才会设为专用并允许该程序的 UDP 29864（音频）和 UDP 29865（发现），仅限本地子网。
更换发行目录或端口后需同步更新防火墙规则。无需在路由器开放互联网端口。

四、声音与延迟
默认 48 kHz、双声道、16 位 PCM，另有加密与网络报头开销。
接收缓冲只是端到端延迟的一部分，不代表实际测得的延迟。
网络抖动时提高缓冲；有线网络可尝试 60–100 ms，Wi-Fi 可从 120–200 ms 开始。
接收音量只改变收到的声音，不改变本机系统音量。
发送端是环回采集，会保留 SUPERU 本地播放。不要通过静音采集设备来消除本地声音，
系统静音 / 设备音量可能同时影响采集；需要完全静音本地同时传送时另需独立音频路由。
独占播放、DRM 内容及部分特殊声卡驱动可能无法采集。换设备后先停止，再刷新并重启音频。
首版一次接收一个发送会话，不支持同一个实例同时发送和接收，避免反馈回路。
当前使用 APCL v1 加密协议，不与 VBAN / Voicemeeter 直接互通。

五、蓝牙模式
在“说明与日志”中点击“打开原版蓝牙接收程序”。从托盘选择手机。
发行包中的 AudioPlaybackConnector64.exe 是未修改的原版；原仓库 C++ 源码已加 LAN 菜单入口，
该菜单入口需要另外用 Visual Studio C++ 构建。局域网模块已经单独编译，可直接使用。

六、设置和日志
保存在 %LOCALAPPDATA%\AudioPlaybackConnectorLAN\ 下。
不保存原始音频，不上传日志，不需要互联网，不自动启动或修改防火墙。
两边默认连接码都是 APCL-HOME-2026，改过会各自保存，日志不记录连接码。
最小化后隐藏到系统托盘，双击图标恢复；关闭窗口退出并停止音频。

七、排查
“发送中”只表示已经发送 UDP 数据，接收成功以接收端状态为准。
无数据：核对目标 IP、端口、防火墙和路由器隔离设置，避免选中 VPN 虚拟网卡 IP。
无效包增加：核对两边连接码完全一致。
有包但无声：确认发送端播放设备选对、接收端音量、耳机连接及系统音量。
更换发送电脑 / 发送端重启后，旧会话空闲 3 秒，新会话才可以接管接收。
